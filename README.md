# nCatViewer

**가볍게 열고, 빠르게 넘기고, 오래 읽는 Rust 기반 로컬 코믹뷰어.**

상태: **Linux M1 개발판 구현 중 · 단일 페이지/폴더/ZIP 수직 경로 실행 가능 · MVP 아님**  
기준일: 2026-11-15

이전 개발 문서는 폐기하고 코믹 감상 중심으로 다시 설계했다. 종합 이미지 도구나 사진 편집기를 만들지 않는다.

## 지금 실행할 수 있는 기능

- GTK4 화면에서 파일·폴더·ZIP/CBZ 열기, 자연 정렬, 이전/다음·번호 이동.
- JPEG/PNG/BMP/WebP·GIF 첫 프레임의 제한된 정지 표시, EXIF 방향·임시 회전.
- 맞춤·확대 미리보기·스크롤/드래그 패닝·전체 화면·좌우 방향키 매핑·파일 드롭.
- 별도 Rust worker, 최신 요청 병합/오래된 결과 거부, 192MiB 예약 예산과 마지막 픽셀 owner까지 유지되는 lease.
- 폴더(현재 폴더만, 하위 폴더 제외)·ZIP/CBZ의 바이트 제한 LRU 페이지 캐시와 진행 방향 인접 페이지 1개 미리 읽기. ZIP 목록/열린 핸들도 재사용합니다.

**RAR·두 장 UI·이어보기·썸네일·고급 맞춤/1:1·ICC 색관리·JPEG 축소 디코딩·4K 최종 화질/타일링은 아직 미구현입니다.** 큰 이미지는 보수적으로 거부될 수 있고 현재 출력은 최대 8MiB 미리보기입니다. 정식 코덱 호환성/보안/성능 게이트를 통과한 제품이 아닙니다.

## Linux 빌드와 실행

GTK4 **4.10 이상** 개발 패키지·pkg-config·Rust toolchain이 필요합니다. 예: Ubuntu 24.04의 `libgtk-4-dev`, CachyOS/Arch의 `gtk4`. Ubuntu에서 실제 실행한 것은 아니며 현재 로컬 검증 환경은 CachyOS/KDE Wayland입니다.

```sh
cargo build --workspace --release --locked
./target/release/ncat-linux
./target/release/ncat-linux /path/to/book.cbz
```

두 실행 파일 `ncat-linux`와 `ncat-worker`는 같은 디렉터리에 있어야 합니다. GUI만 `cargo run`하면 worker가 빌드되지 않을 수 있으므로 workspace를 먼저 빌드하세요. 개발 중 worker 위치를 바꾸려면 명시적으로 `NCAT_WORKER`를 지정합니다. 파일 경로나 PATH에서 임의 실행 파일을 찾지 않습니다.

메모리 관련 설정은 실행 시 검증하며 잘못된 값은 실행을 거부합니다. 지속 설정 파일/UI는 아직 없습니다.

| 환경변수 | 기본값 | 범위/의미 |
|---|---:|---|
| `NCAT_MEMORY_MIB` | 192 | 1~384, 이미지 관련 총 예약 예산(RSS 아님) |
| `NCAT_CACHE_MIB` | 총 예산의 1/8 | 0~총 예산의 1/3, 픽셀+키 상한; 0은 캐시 끔 |
| `NCAT_WORKSPACE_MIB` | 128 | 8~384, 실제 작업은 총 예산의 남은 공간으로 추가 제한 |
| `NCAT_TIMEOUT_SECS` | 15 | 1~120, 작업별 deadline |
| `NCAT_PREFETCH` | 1 | 0/1 또는 false/true |

기본 캐시는 24MiB입니다. 캐시의 프레임은 CPU/GUI staging을 포함한 기존 예약을 공유하므로 실제 전역 예약은 픽셀 상한보다 클 수 있습니다. 공간이 부족하면 캐시를 먼저 비우고 전경 작업을 한 번 재시도합니다. 소스 변경·재열기·보기 조건이 달라지면 이전 결과를 잘못 재사용하지 않습니다. 미지원 RAR/7Z에는 아직 적용되지 않습니다.

워커가 원본 변경 오류를 반환하면 부모가 리비전을 재검사합니다. 실제 변경은 차단하고, 그대로라면 워커 세션을 한 번만 다시 열어 복구합니다. 재시도도 모순된 변경 오류를 반환하면 원본 변경이 아닌 워커 응답 오류로 구분합니다.

### 오류 진단 로그

원본 변경 판정·워커 오류·복구 시도/결과가 발생하면 **실행한 현재 디렉터리의 `log/ncat-incident-*.log`**에 자동 기록합니다. 프로젝트 루트에서 실행하면 루트의 `log/`에 저장됩니다. 정상 탐색은 직전 128개 상태만 메모리에 보관하고 디스크에 계속 쓰지 않습니다.

- 발생 시각·경과 시간·요청 세대/책 epoch·보기 크기/회전·캐시/예약 bytes·워커 재시작/복구 통계·원본 리비전의 어떤 필드가 달라졌는지를 기록합니다.
- 파일명·원본 경로·압축 항목명·페이지 번호·이미지/메타데이터 내용은 기록하지 않으며 외부 전송도 없습니다.
- 앱 전용 이름의 로그만 최근 최대 8개 유지합니다(파일당 약 128KiB 상한, 동시 실행 시 일시 초과 가능). 다른 파일은 삭제하지 않습니다. 로그 파일 권한은 사용자 전용 `0600`입니다.
- 저장할 수 없으면 정제된 경고를 stderr에 한 번 표시하고 읽기는 계속합니다. 오류가 재발하면 `log/`의 최신 로그를 전달해 주세요. 직접 삭제해도 실행에는 영향이 없습니다.

빠른 이동/메모리 재현용 테스트 모드(정상 실행에서는 자동 이동하지 않음):

```sh
python3 tools/measure-smoke.py -- target/release/ncat-linux --smoke-navigation /path/to/book.zip
```

첫 표시 뒤 5ms 타이머로 500회 이동을 요청하고, 최신 페이지 texture 생성 확인 후 5초 유지·자동 종료합니다. 중간 오류/최종 표시 실패는 실패 종료합니다. 실제 키 입력 지연·compositor 제시 시간·전체 책 페이지 검증을 대신하지 않습니다.

초기 메모리 비교용으로 GTK의 Cairo 소프트웨어 경로도 사용할 수 있습니다. 로컬 작은 CBZ smoke에서는 기본 renderer보다 메모리가 적었지만 4K/CPU/반응성 검증이 남아 있어 기본값으로 강제하지 않습니다.

```sh
GSK_RENDERER=cairo ./target/release/ncat-linux /path/to/book.cbz
```

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

키: Ctrl+O 파일, Ctrl+Shift+O 폴더, Space/PageDown 다음, Backspace/PageUp 이전, ←/→ 읽기 방향, D 방향 전환, +/- 확대, 9 맞춤, R/Shift+R 회전, F5 다시 열기, F11 전체 화면, Ctrl+Q 종료. 입력 위젯의 Tab/Enter/Space는 기본 동작을 유지합니다. 기록은 현재 전혀 저장하지 않습니다.

## 제품의 목표 방향

- 폴더와 ZIP/CBZ·RAR/CBR, 이후 7Z/CB7·TAR/CBT의 이미지를 수동 전체 압축 해제 없이 읽는다.
- 기본 이미지부터 AVIF/JXL 등까지 지원을 넓히되 실제 배포본으로 검증한 형식만 지원 목록에 올린다.
- 한 장/두 장 보기·좌우 읽기 방향·맞춤·확대·이어보기 등 코믹 감상 기능에 집중한다.
- 업무 로직은 Rust. 페이지 크기 중심 디코딩·바이트 예산·짧은 미리 읽기·최신 요청 우선으로 메모리와 반응성을 최적화한다.
- Linux x64부터 개발·검증한다. Linux GUI는 gtk-rs/GTK4를 우선 검증하며, 다른 OS의 GUI·패키지는 현재 만들지 않는다.
- 편집·변환·필터·주석·파일 이동/삭제·라이브러리 인덱싱·클라우드·AI 기능은 제외한다.

참고 방향은 Windows 꿀뷰의 간결한 파일/압축 감상과 Android 코믹 리더의 읽기 흐름이다. 특정 Android “코믹뷰” 앱의 링크/버전은 아직 지정되지 않아 공통 UX 패턴만 참고한다. 앱 코드·아이콘·화면 자산은 복제하지 않는다.
